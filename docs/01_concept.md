# КиноНить — Этап 1: Игровой дизайн и продукт

## 1. Core Loop

**КиноНить** — это одиночная игра-головоломка, в которой игрок строит цепочку актёров и фильмов от стартового актёра до целевого актёра. Каждый переход должен быть обоснован: два соседних актёра в цепочке обязаны сниматься в одном и том же фильме.

Базовая логическая модель игры:

```text
Актёр → Фильм → Актёр → Фильм → … → Целевой актёр
```

Игрок не вводит названия фильмов и не ищет связи вручную через поисковик. Игра показывает ему доступные фильмы текущего актёра, а затем — актёров выбранного фильма. Игрок принимает решения и постепенно приближается к цели.

### 1.1. Пошаговое описание цикла

1. Игрок запускает партию.
2. Игра генерирует пару: **Стартовый актёр → Целевой актёр**.
3. Игра проверяет, что между актёрами существует хотя бы один валидный путь.
4. Игра показывает стартового актёра, целевого актёра и пустую цепочку.
5. Стартовый актёр становится текущим актёром.
6. Игрок открывает список фильмов, в которых текущий актёр снялся.
7. Игрок выбирает один фильм из списка.
8. Игра загружает актёрский состав выбранного фильма.
9. Игра показывает актёров, которые также снялись в этом фильме.
10. Игрок выбирает следующего актёра.
11. Игра показывает подтверждение перехода.
12. Игрок подтверждает выбор.
13. Игра добавляет в цепочку выбранный фильм и нового актёра.
14. Новый актёр становится текущим.
15. Игра проверяет, совпадает ли текущий актёр с целевым.
16. Если совпадает — партия завершается победой.
17. Если не совпадает — игрок возвращается к выбору следующего фильма.
18. Цикл повторяется до победы, сдачи, ошибки или тупика.
19. После завершения партия показывает результат и полную цепочку.

### 1.2. Пример успешной партии

Пусть стартовый актёр — **Актёр A**, а целевой — **Актёр D**.

1. Игра показывает:

```text
Старт: Актёр A
Цель: Актёр D
```

2. Игрок открывает фильмы Актёра A.
3. Игрок выбирает `Фильм 1`.
4. В `Фильме 1` также снимался Актёр B.
5. Игрок выбирает Актёра B.
6. Цепочка обновляется:

```text
Актёр A
  → Фильм 1
  → Актёр B
```

7. Игрок открывает фильмы Актёра B.
8. Игрок выбирает `Фильм 2`.
9. В `Фильме 2` также снимался Актёр C.
10. Игрок выбирает Актёра C.
11. Цепочка обновляется:

```text
Актёр A
  → Фильм 1
  → Актёр B
  → Фильм 2
  → Актёр C
```

12. Игрок открывает фильмы Актёра C.
13. Игрок выбирает `Фильм 3`.
14. В `Фильме 3` также снимался Актёр D.
15. Игрок выбирает Актёра D.
16. Игра фиксирует победу.
17. Итоговая цепочка:

```text
Актёр A
  → Фильм 1
  → Актёр B
  → Фильм 2
  → Актёр C
  → Фильм 3
  → Актёр D
```

### 1.3. Что считается шагом

Шагом считается один валидный переход:

```text
Текущий актёр → Фильм → Новый актёр
```

Пример:

```text
Актёр A → Фильм 1 → Актёр B → Фильм 2 → Актёр C → Фильм 3 → Актёр D
```

Здесь:

- Актёров в цепочке: 4.
- Фильмов-переходов: 3.
- Шагов: 3.

Целевой актёр уже входит в цепочку, поэтому отдельный шаг для его «добавления» не требуется.

### 1.4. Правила валидного перехода

Переход допустим только при выполнении всех условий:

1. Текущий актёр указан в актёрском составе выбранного фильма.
2. Новый актёр также указан в актёрском составе этого фильма.
3. Новый актёр не совпадает с текущим актёром.
4. Фильм имеет валидный TMDB `movie_id`.
5. Актёр имеет валидный TMDB `person_id`.
6. Переход не нарушает ограничения на повторное использование актёров и фильмов.
7. Переход не создаёт бесконечный цикл.

### 1.5. Недопустимые переходы

| Ситуация | Почему недопустимо |
|---|---|
| Актёр → Актёр | Не указан фильм, через который они связаны |
| Фильм → Фильм | Не указан общий актёр |
| Актёр → Фильм, где его нет | Нарушено условие участия актёра в фильме |
| Фильм → Актёр, которого нет в фильме | Нарушено условие участия актёра в фильме |
| Актёр → тот же актёр | Переход не приближает к цели и не имеет смысла |
| Фильм → тот же фильм без нового актёра | Не создаёт валидного перехода |

### 1.6. Состояния активной партии

| Состояние | Описание |
|---|---|
| Новая партия | Игра готовит пару и начальные данные |
| Выбор фильма | Игрок выбирает фильм с участием текущего актёра |
| Загрузка актёров фильма | Игра получает актёрский состав выбранного фильма |
| Выбор следующего актёра | Игрок выбирает актёра из выбранного фильма |
| Подтверждение перехода | Игрок подтверждает или отменяет новый шаг |
| Цель достигнута | Текущий актёр совпадает с целевым |
| Партия завершена | Игрок видит результат |
| Ошибка данных | Игра не смогла получить или проверить необходимые данные |
| Нет доступных переходов | У текущего актёра нет подходящих фильмов или актёров |

### 1.7. Что игрок не делает

В рамках базовой версии игрок не:

- Не вводит названия фильмов вручную.
- Не редактирует уже построенную цепочку.
- Не удаляет произвольные промежуточные шаги.
- Не играет против другого игрока.
- Не покупает подсказки или внутриигровые предметы.
- Не проходит уровни с фиксированным прогрессом.
- Не собирает валюту, достижения или коллекционные объекты.

Эти механики не входят в текущую постановку задачи.

## 2. Экраны приложения

### 2.1. Экран запуска

**Назначение:** дать игроку понятную точку входа и объяснить суть игры.

Игрок видит:

- Название игры.
- Краткое описание: «Постройте цепочку от одного актёра к другому через фильмы».
- Кнопку **«Начать игру»**.
- Кнопку **«Как играть»**.
- Индикатор доступности данных, если игра не может подключиться к TMDB.

Доступные действия:

- Начать новую партию.
- Открыть правила.
- Повторить попытку подключения, если источник данных недоступен.

### 2.2. Экран правил

**Назначение:** объяснить правила до первой партии.

Игрок видит:

- Цель партии.
- Схему связи:

```text
Актёр → Фильм → Актёр
```

- Правило, что два соседних актёра должны сниматься в одном фильме.
- Пример короткой цепочки.
- Объяснение, что партия завершается при достижении целевого актёра.
- Основные ограничения:
  - Нельзя выбрать фильм, в котором нет текущего актёра.
  - Нельзя выбрать актёра, которого нет в выбранном фильме.
  - Нельзя перейти к актёру напрямую, минуя фильм.

Доступные действия:

- Вернуться на экран запуска.
- Начать игру.

### 2.3. Экран генерации партии

**Назначение:** показать игроку, что игра готовит новую задачу.

Игрок видит:

- Анимацию или текст состояния: «Генерируем пару…».
- При необходимости — прогресс подготовки.
- Сообщение об ошибке, если пару сгенерировать не удалось.
- Кнопку **«Повторить»** при ошибке.

Доступные действия:

- Дождаться завершения генерации.
- Отменить ожидание и вернуться назад, если это предусмотрено интерфейсом.
- Повторить генерацию после ошибки.

### 2.4. Экран активной партии

Это центральный экран игры.

**Назначение:** дать игроку всю информацию, необходимую для построения цепочки.

Игрок видит:

- Стартового актёра.
- Целевого актёра.
- Текущего актёра — вершину, от которой строится следующий переход.
- Текущую цепочку.
- Количество уже сделанных шагов.
- Таймер партии, если он включён в базовой версии.
- Кнопку **«Выбрать фильм»**.
- Кнопку **«Сдаться»** или **«Завершить партию»**.
- Кнопку **«Начать заново»**.
- Подсказку о следующем действии.

Доступные действия:

- Открыть список фильмов текущего актёра.
- Выбрать фильм.
- Посмотреть цепочку.
- Завершить партию досрочно.
- Начать партию заново.

### 2.5. Экран выбора фильма

**Назначение:** позволить игроку выбрать фильм, связывающий текущего актёра со следующим актёром.

Игрок видит:

- Имя текущего актёра.
- Заголовок: «Выберите фильм с участием [имя актёра]».
- Список фильмов, в которых текущий актёр имеет актёрскую роль.
- Для каждого фильма:
  - Название.
  - Год выпуска, если доступен.
  - Постер, если доступен.
  - Краткую информацию о роли, если она доступна.
- Состояние загрузки списка.
- Сообщение «Фильмы не найдены», если список пуст.
- Сообщение об ошибке, если список не удалось загрузить.
- Кнопку «Назад».

Доступные действия:

- Просмотреть список фильмов.
- Выбрать фильм.
- Вернуться к активной партии.
- Обновить список после ошибки загрузки.

### 2.6. Экран выбора следующего актёра

**Назначение:** позволить игроку выбрать актёра, который также снялся в выбранном фильме.

Игрок видит:

- Название выбранного фильма.
- Имя текущего актёра.
- Заголовок: «Кого выберете из фильма [название фильма]?»
- Список актёров из фильма.
- Для каждого актёра:
  - Имя.
  - Фото, если доступно.
  - Роль или персонаж, если данные доступны.
  - Пометку «Цель», если это целевой актёр.
- Состояние загрузки.
- Сообщение «Актёры не найдены», если список пуст.
- Сообщение об ошибке, если список не удалось загрузить.
- Кнопку «Назад».

Доступные действия:

- Просмотреть список актёров.
- Выбрать следующего актёра.
- Вернуться к выбору фильма.
- Обновить список после ошибки загрузки.

### 2.7. Экран подтверждения перехода

**Назначение:** предотвратить случайный выбор и показать игроку, как новый шаг повлияет на цепочку.

Игрок видит:

- Текущего актёра.
- Выбранный фильм.
- Выбранного следующего актёра.
- Предварительный вариант новой цепочки.
- Кнопку **«Подтвердить»**.
- Кнопку **«Отменить»**.

Доступные действия:

- Подтвердить переход.
- Отменить переход.
- Вернуться к выбору фильма или актёра.

Экран подтверждения может быть реализован как отдельный экран или модальное окно. Важно, чтобы игрок до фиксации шага видел будущий фрагмент цепочки:

```text
Актёр B
  → Фильм 2
  → Актёр C
```

### 2.8. Экран победы

**Назначение:** зафиксировать успешное завершение партии.

Игрок видит:

- Сообщение «Цель достигнута».
- Стартового и целевого актёров.
- Полную цепочку.
- Количество шагов.
- Время партии.
- Количество просмотренных фильмов и актёров, если эти метрики доступны.
- Кнопку **«Новая партия»**.
- Кнопку **«Посмотреть цепочку»**.
- Кнопку **«В меню»**.

Доступные действия:

- Начать новую партию.
- Просмотреть детальную цепочку.
- Вернуться на главный экран.

### 2.9. Экран результата без победы

**Назначение:** корректно завершить партию, если игрок сдался, отменил игру или не смог продолжить.

Игрок видит:

- Сообщение «Партия завершена».
- Причину завершения:
  - Игрок сдался.
  - Игрок начал новую партию.
  - Не найдено доступных переходов.
  - Произошла ошибка данных.
- Частично построенную цепочку, если она есть.
- Кнопку **«Новая партия»**.
- Кнопку **«В меню»**.

Доступные действия:

- Начать новую партию.
- Вернуться в меню.
- Просмотреть текущую цепочку.

### 2.10. Экран ошибки

**Назначение:** сообщить игроку о проблеме и предложить понятное действие.

Игрок видит:

- Понятный заголовок ошибки.
- Короткое объяснение без технических деталей.
- Возможную причину:
  - Нет соединения с интернетом.
  - Данные временно недоступны.
  - Не удалось загрузить фильмы.
  - Не удалось загрузить актёров.
  - Не удалось сгенерировать пару.
  - Превышен лимит запросов.
- Кнопку **«Повторить»**, если повтор возможен.
- Кнопку **«В меню»**.

Доступные действия:

- Повторить действие.
- Вернуться в меню.
- Начать новую партию, если текущая партия не может быть продолжена.

### 2.11. Экран просмотра цепочки

**Назначение:** показать итоговый или текущий маршрут игрока.

Игрок видит:

- Полную цепочку в читаемом виде.
- Каждый переход отдельно.
- Названия фильмов и имена актёров.
- Пометку стартового и целевого актёров.
- Метрики партии: шаги, время, дата.

Доступные действия:

- Вернуться к результату.
- Начать новую партию.
- Вернуться в меню.

## 3. UX-флоу

### 3.1. Основной путь пользователя

```text
Запуск приложения
  → Экран запуска
  → «Как играть»
  → Экран правил
  → «Начать игру»
  → Генерация пары
  → Активная партия
  → Выбор фильма
  → Выбор следующего актёра
  → Подтверждение перехода
  → Повторение выбора фильма и актёра
  → Достижение целевого актёра
  → Экран победы
  → Просмотр цепочки
  → Новая партия или выход в меню
```

### 3.2. Первый запуск

1. Игрок открывает приложение.
2. Игра показывает экран запуска.
3. Игрок нажимает **«Как играть»**.
4. Игра объясняет, что нужно соединить двух актёров через фильмы.
5. Игрок видит пример:

```text
Актёр A → Фильм 1 → Актёр B → Фильм 2 → Актёр C
```

6. Игрок нажимает **«Начать игру»**.
7. Игра генерирует пару.
8. Игра проверяет существование пути.
9. Игрок попадает на экран активной партии.

### 3.3. Построение цепочки

1. На экране активной партии игрок видит стартового и целевого актёров.
2. Текущим актёром изначально является стартовый актёр.
3. Игрок нажимает **«Выбрать фильм»**.
4. Игра запрашивает фильмографию текущего актёра.
5. Игра показывает фильмы, где текущий актёр снялся.
6. Игрок выбирает фильм.
7. Игра запрашивает актёрский состав фильма.
8. Игра показывает актёров этого фильма.
9. Игрок выбирает следующего актёра.
10. Игра показывает подтверждение перехода.
11. Игрок подтверждает выбор.
12. Новый актёр становится текущим.
13. Цепочка обновляется.
14. Если новый актёр — целевой, партия завершается победой.
15. Если нет, игрок возвращается к выбору фильма.

### 3.4. Успешное завершение

1. Игрок выбирает фильм, в котором текущий актёр и целевой актёр снимались вместе.
2. В списке актёров фильма целевой актёр отмечается как цель.
3. Игрок выбирает целевого актёра.
4. Игра показывает подтверждение.
5. Игрок подтверждает переход.
6. Игра фиксирует победу.
7. Игрок видит экран победы.
8. Игра показывает итоговую цепочку и статистику.
9. Игрок может начать новую партию.

### 3.5. Досрочное завершение

1. Во время активной партии игрок нажимает **«Сдаться»**.
2. Игра показывает подтверждение: «Завершить текущую партию?»
3. Игрок подтверждает.
4. Игра сохраняет факт досрочного завершения.
5. Игрок попадает на экран результата без победы.
6. Игрок может просмотреть построенную часть цепочки.
7. Игрок может начать новую партию.

### 3.6. Ошибка во время партии

1. Игрок нажимает **«Выбрать фильм»**.
2. Игра пытается загрузить список фильмов.
3. Запрос завершается ошибкой или отсутствует сеть.
4. Игра показывает экран ошибки или встроенное сообщение об ошибке.
5. Игрок нажимает **«Повторить»**.
6. Если повтор успешен, игрок возвращается к выбору фильма.
7. Если повтор невозможен, игрок может завершить партию или вернуться в меню.

### 3.7. Тупиковая ситуация

1. Игрок выбирает текущего актёра.
2. Игра пытается показать фильмы с его участием.
3. Подходящих фильмов нет.
4. Игра сообщает: «У этого актёра нет доступных фильмов для продолжения».
5. Игрок может:
   - Вернуться к предыдущему шагу, если отмена перехода доступна.
   - Завершить партию.
   - Начать новую партию.

В базовой версии важно честно сообщать игроку, что дальнейшее движение невозможно, а не оставлять его с пустым списком без объяснения.

## 4. Правила генерации пары

Пары должны генерироваться динамически, но не быть случайными в худшем смысле: пара обязана быть решаемой и интересной.

### 4.1. Базовые требования к паре

Каждая сгенерированная пара должна удовлетворять следующим условиям:

1. Стартовый и целевой актёры должны быть разными.
2. Между ними должен существовать хотя бы один валидный путь через фильмы.
3. Путь должен состоять только из валидных переходов:

```text
Актёр → Фильм → Актёр
```

4. Каждый фильм в пути должен содержать обоих соседних актёров.
5. Целевой актёр должен быть достижим из стартового.
6. Пара не должна быть тривиальной, если это не предусмотрено режимом сложности.
7. Пара не должна требовать бесконечного поиска: генератор должен остановиться по ограничению глубины, времени или числа запросов.

### 4.2. Связность

Связность означает, что от стартового актёра до целевого существует маршрут.

Минимально допустимый маршрут:

```text
Стартовый актёр → Фильм → Целевой актёр
```

Такой маршрут допустим, но обычно не должен быть основным вариантом генерации, потому что делает задачу слишком простой.

Более интересный маршрут:

```text
Стартовый актёр
  → Фильм 1
  → Актёр B
  → Фильм 2
  → Актёр C
  → Фильм 3
  → Целевой актёр
```

Здесь между стартовым и целевым актёрами есть два промежуточных актёра и три фильма.

### 4.3. Длина пути

Длина пути измеряется числом переходов:

```text
Актёр → Фильм → Актёр
```

| Длина пути | Пример | Ощущение игрока |
|---:|---|---|
| 1 | Стартовый и целевой в одном фильме | Очень просто |
| 2 | Один промежуточный актёр, два фильма | Просто |
| 3 | Два промежуточных актёра, три фильма | Средняя сложность |
| 4 | Три промежуточных актёра, четыре фильма | Сложно |
| 5 и более | Четыре и более промежуточных актёров | Очень сложно |

Для первой версии продукта целевая длина может быть задана диапазоном, например:

- Минимум: 2 шага.
- Предпочтительно: 3–5 шагов.
- Максимум: 6–8 шагов.

Точные значения настраиваются на этапе генерации и могут зависеть от желаемой сложности.

### 4.4. Сложность пары

Сложность не должна определяться только длиной пути.

На неё влияют:

- Количество промежуточных актёров.
- Количество фильмов, доступных на каждом шаге.
- Известность актёров и фильмов.
- Наличие коротких альтернативных путей.
- Вероятность того, что игрок найдёт очевидную связь.
- Ограничение на использование уже посещённых актёров или фильмов.

Пример: пара с тремя шагами может быть проще пары с двумя шагами, если у промежуточных актёров очень много известных фильмов и много очевидных связей.

### 4.5. Требования к качеству пары

Хорошая пара должна:

- Иметь гарантированный путь.
- Не быть слишком очевидной.
- Не требовать нереалистично длинного поиска.
- Использовать актёров с достаточным количеством фильмов.
- Не опираться на фильмы с неполными или ошибочными данными.
- Не создавать ситуацию, в которой игрок заходит в тупик без возможности продолжить.
- Быть воспроизводимой для отладки, если игра сохраняет параметры генерации.

### 4.6. Ограничения генерации

Генератор должен иметь ограничения:

- Максимальная глубина поиска.
- Максимальное число кандидатов на каждом шаге.
- Максимальное число TMDB-запросов на одну генерацию.
- Максимальное время генерации.
- Минимальная и максимальная длина пути.
- Правило запрета повторов актёров в пределах одной цепочки, если оно выбрано.
- Правило запрета повторов фильмов в пределах одной цепочки, если оно выбрано.

Эти ограничения нужны, чтобы генерация не превращалась в бесконечный обход графа и не создавала чрезмерную нагрузку на TMDB.

### 4.7. Что не входит в этап 1

На данном этапе не проектируются:

- Конкретный алгоритм поиска пути.
- Формулы оценки сложности.
- Кэширование графа.
- Хранение истории партий.
- Ранжирование актёров по популярности.
- Локальные базы данных.
- Серверная генерация.

Детали алгоритма будут рассмотрены на Этапе 4.

## 5. Ограничения TMDB API

TMDB является внешним источником данных, поэтому игра должна работать с учётом сетевых задержек, лимитов, ошибок и неполноты данных.

### 5.1. Базовый адрес API

TMDB API v3 использует базовый адрес:

```text
https://api.themoviedb.org/3
```

Все эндпоинты ниже указываются относительно этого адреса.

Например, путь:

```text
/person/{person_id}/movie_credits
```

означает полный URL:

```text
https://api.themoviedb.org/3/person/{person_id}/movie_credits
```

### 5.2. Лимиты запросов

По официальной документации TMDB, прежний жёсткий лимит «40 запросов каждые 10 секунд» отключён с декабря 2019 года. Однако у сервиса остаются верхние ограничения для предотвращения массового скрейпинга; они находятся примерно в районе 40 запросов в секунду и могут изменяться.

Практические выводы для игры:

- Нельзя считать, что запросы бесплатны и неограниченны.
- Нужно предусматривать ответ `429 Too Many Requests`.
- Нужно ограничивать количество параллельных запросов.
- Нужна очередь или троттлинг запросов.
- Нужны повторные попытки с задержкой при временных ошибках.
- Генерация пары не должна выполнять неконтролируемо большое число запросов.
- Во время активной партии запросы должны быть компактными и целевыми.

### 5.3. Необходимые эндпоинты

| Назначение | Метод | Эндпоинт TMDB v3 | Зачем нужен |
|---|---:|---|---|
| Поиск актёра по имени | `GET` | `/search/person` | Найти TMDB `person_id` по имени актёра |
| Данные актёра | `GET` | `/person/{person_id}` | Получить имя, фото и базовую информацию об актёре |
| Фильмография актёра | `GET` | `/person/{person_id}/movie_credits` | Получить фильмы, в которых актёр снимался |
| Актёрский состав фильма | `GET` | `/movie/{movie_id}/credits` | Получить список актёров конкретного фильма |
| Детали фильма | `GET` | `/movie/{movie_id}` | Получить название, дату выхода, постер и другие базовые данные |
| Поиск фильма | `GET` | `/search/movie` | Найти фильм по названию; используется для валидации, отладки или ручного поиска в будущих версиях |
| Конфигурация изображений | `GET` | `/configuration` | Получить базовый URL и правила сборки ссылок на постеры и фото |

### 5.4. Полные URL эндпоинтов

```text
GET https://api.themoviedb.org/3/search/person
GET https://api.themoviedb.org/3/person/{person_id}
GET https://api.themoviedb.org/3/person/{person_id}/movie_credits
GET https://api.themoviedb.org/3/movie/{movie_id}/credits
GET https://api.themoviedb.org/3/movie/{movie_id}
GET https://api.themoviedb.org/3/search/movie
GET https://api.themoviedb.org/3/configuration
```

### 5.5. Роли эндпоинтов в игровом цикле

#### Поиск актёра

Используется, когда игра знает имя актёра, но не знает его TMDB ID.

```text
Имя актёра
  → GET /search/person
  → person_id
```

Этот эндпоинт особенно важен для генерации пары и для обработки пользовательского ввода, если он появится в будущих версиях.

#### Фильмография актёра

Используется на экране выбора фильма.

```text
Текущий актёр
  → GET /person/{person_id}/movie_credits
  → список фильмов с его участием
```

Игра должна показывать только фильмы, где актёр указан в актёрском составе, если базовое правило требует именно актёрской связи. Режиссёрские, сценарные или продюсерские роли не должны автоматически считаться основанием для перехода, если это не оговорено отдельно.

#### Актёрский состав фильма

Используется на экране выбора следующего актёра.

```text
Выбранный фильм
  → GET /movie/{movie_id}/credits
  → список актёров фильма
```

Игра должна использовать `cast` из ответа, чтобы определить, с кем текущий актёр связан через выбранный фильм.

#### Детали фильма

Используются для отображения понятной игроку информации:

- Название фильма.
- Год выпуска.
- Постер.
- Дополнительные сведения, если они нужны интерфейсу.

#### Конфигурация изображений

TMDB обычно возвращает пути к изображениям, а не полностью готовые URL. Поэтому игре может понадобиться эндпоинт:

```text
GET /configuration
```

Он помогает получить базовый URL изображений и допустимые размеры, чтобы корректно собрать ссылки на постеры и фотографии актёров.

### 5.6. Минимальный набор для MVP

Для базового игрового цикла **обязательно** нужны четыре эндпоинта:

```text
GET /search/person
GET /person/{person_id}/movie_credits
GET /movie/{movie_id}/credits
GET /movie/{movie_id}
```

Они обеспечивают всю цепочку:

```text
Имя актёра
  → /search/person
  → person_id

Текущий актёр
  → /person/{person_id}/movie_credits
  → список фильмов

Выбранный фильм
  → /movie/{movie_id}/credits
  → список актёров

Следующий актёр
  → следующий переход
```

Эндпоинт `/movie/{movie_id}` не обязателен для самого перехода, если название и дата уже есть в `movie_credits`, но он нужен для экрана фильма, постера и более полной информации.

### 5.7. Эндпоинты, необязательные на старте

Эти эндпоинты не обязательны для минимальной версии:

```text
GET /search/movie
GET /configuration
```

`/search/movie` нужен только если вы хотите искать фильмы по названию. `/configuration` нужен, если вы хотите корректно строить URL изображений TMDB; без него можно временно не показывать постеры и фото.

### 5.8. Ограничения данных TMDB

Даже при доступном API данные могут быть неполными или неоднородными:

- У фильма может не быть указан полный актёрский состав.
- У актёра может быть мало фильмов.
- Имена актёров могут повторяться.
- Один человек может иметь несколько записей в TMDB.
- Фильм может быть отменён, не выпущен или иметь некорректную дату.
- Постер или фото актёра могут отсутствовать.
- Названия и описания зависят от выбранного языка.
- Кредиты могут содержать не только актёров, но и членов съёмочной группы.
- Порядок актёров в списке не обязательно отражает их значимость.

Игра должна воспринимать TMDB как источник, который может возвращать неполные, изменяющиеся или неоднозначные данные.

### 5.9. Политика работы с API

Базовые требования:

- Все сетевые запросы должны иметь таймаут.
- Ошибки сети, авторизации, лимитов и сервера должны различаться.
- Ответ `429 Too Many Requests` должен обрабатываться отдельной стратегией ожидания и повтора.
- Не следует выполнять запросы для всех актёров и фильмов заранее без необходимости.
- Не следует запрашивать данные повторно без причины в рамках одной сессии.
- Генератор должен вести учёт числа запросов.
- Интерфейс должен показывать состояние загрузки, а не «зависать» без обратной связи.
- При отсутствии сети игра должна сообщать об этом понятным языком.

## 6. Edge cases

### 6.1. Между актёрами нет пути

**Сценарий:** генератор выбрал стартового и целевого актёров, но не смог найти ни одного валидного маршрута.

**Почему может произойти:**

- Актёры находятся в разных несвязанных частях графа.
- Ограничение глубины поиска слишком мало.
- У одного из актёров мало фильмов.
- Данные TMDB неполны.
- Фильтры генерации слишком строгие.

**Ожидаемое поведение:**

- Генератор не показывает игроку нерешаемую пару.
- Генератор пробует другую пару.
- Если несколько попыток подряд не удались, игра показывает сообщение: «Не удалось подобрать подходящую пару. Попробуйте ещё раз».
- Игра не должна начинать партию без подтверждённого пути.

### 6.2. TMDB недоступен

**Сценарий:** нет интернета, TMDB не отвечает, запрос отклонён или сервер возвращает ошибку.

**Почему может произойти:**

- У игрока отсутствует сеть.
- TMDB временно недоступен.
- Запрос превысил таймаут.
- Возникла ошибка DNS, прокси, сертификата или firewall.
- API вернул `5xx`.

**Ожидаемое поведение:**

- Игра не должна выдавать техническую ошибку без объяснения.
- Игрок должен увидеть сообщение: «Не удалось подключиться к базе фильмов. Проверьте интернет и попробуйте снова».
- Игра должна предложить повторить действие.
- Если ошибка возникла при генерации пары, партия не должна начинаться.
- Если ошибка возникла во время партии, игрок должен иметь возможность повторить текущее действие или завершить партию.

### 6.3. Превышен лимит запросов TMDB

**Сценарий:** игра отправляет слишком много запросов, и TMDB возвращает `429 Too Many Requests`.

**Почему может произойти:**

- Генератор слишком агрессивно обходит граф.
- Игра выполняет много параллельных запросов.
- Несколько игроков или устройств используют один и тот же API-ключ.
- Произошёл повторный запуск тяжёлой генерации.

**Ожидаемое поведение:**

- Игра распознаёт `429`.
- Игра приостанавливает отправку новых запросов.
- Игра повторяет запрос позже с увеличенной задержкой.
- Игрок видит нейтральное сообщение: «Слишком много запросов к базе фильмов. Подождите немного».
- Генерация пары не должна бесконечно повторяться.
- Если лимит не снимается, игра должна предложить вернуться в меню или повторить позже.

### 6.4. Зацикливание в цепочке

**Сценарий:** игрок выбирает актёров и фильмы так, что снова и снова возвращается к уже посещённым вершинам.

**Пример:**

```text
Актёр A → Фильм 1 → Актёр B → Фильм 2 → Актёр A
```

**Почему это проблема:**

- Игрок может бесконечно ходить по кругу.
- Цепочка становится запутанной.
- Генератор может бесконечно обходить одни и те же узлы.
- Может увеличиться число TMDB-запросов.

**Ожидаемое поведение:**

- Игра должна отслеживать уже посещённых актёров в текущей цепочке.
- Игра должна отслеживать уже использованные фильмы, если это предусмотрено правилами.
- Уже использованные актёры могут быть визуально отмечены.
- Повторный выбор может быть запрещён или разрешён в зависимости от правила режима.
- В базовой версии предпочтительно запрещать повторное использование одного и того же актёра в одной цепочке.
- Генератор обязан иметь ограничение глубины и числа посещённых узлов.

### 6.5. У текущего актёра нет фильмов

**Сценарий:** игрок выбрал актёра, у которого в TMDB нет актёрских кредитов или они не загрузились.

**Почему может произойти:**

- Актёр действительно не имеет актёрских ролей.
- Данные о кредитах отсутствуют.
- Произошла ошибка загрузки.
- Фильмы актёра отфильтрованы как неподходящие.
- Актёр был выбран ошибочно.

**Ожидаемое поведение:**

- Игра показывает: «У этого актёра нет доступных фильмов для продолжения».
- Игра не должна показывать пустой список без объяснения.
- Игрок должен иметь возможность вернуться к предыдущему шагу, если это предусмотрено.
- Игра должна предложить завершить партию или начать новую.
- Генератор должен стараться не выбирать таких актёров как обязательные промежуточные вершины.

### 6.6. В выбранном фильме нет других актёров

**Сценарий:** игрок выбрал фильм, но в его актёрском составе нет никого, кроме текущего актёра, либо список актёров пуст.

**Почему может произойти:**

- Данные о `cast` неполны.
- Фильм является документальным, короткометражным или специализированным проектом.
- Актёрский состав не был загружен.
- Игра ошибочно отфильтровала всех кандидатов.

**Ожидаемое поведение:**

- Игра показывает: «В этом фильме не найдено других актёров».
- Игрок может вернуться к выбору другого фильма.
- Игра не должна считать такой выбор переходом.
- Игра не должна блокировать игрока навсегда: он должен иметь возможность выбрать другой фильм.

### 6.7. Целевой актёр отсутствует в списке кандидатов

**Сценарий:** игрок открыл фильм, в котором по данным должен сниматься целевой актёр, но его нет в отображаемом списке.

**Почему может произойти:**

- Данные о `cast` неполны.
- Целевой актёр указан в `crew`, но не в `cast`.
- Имя отображается некорректно.
- Игра ограничила число отображаемых актёров.
- Произошла ошибка загрузки.

**Ожидаемое поведение:**

- Игра не должна утверждать, что целевой актёр точно есть в фильме, если его нет в загруженном списке.
- Если целевой актёр не найден в списке, игрок должен иметь возможность выбрать другого актёра или другой фильм.
- Игра должна показать сообщение: «Целевой актёр не найден в актёрском составе этого фильма».
- Генератор должен проверять наличие целевого актёра именно в `cast`, а не только в общих creditах.

### 6.8. Дубликаты актёров или фильмов

**Сценарий:** один и тот же актёр или фильм появляется в списке несколько раз.

**Почему может произойти:**

- В TMDB есть несколько записей для одного человека.
- Фильм имеет несколько версий или связанных записей.
- Кредиты содержат дубликаты.
- Игра объединяет данные из разных запросов.

**Ожидаемое поведение:**

- Игра должна дедуплицировать актёров по TMDB `person_id`.
- Игра должна дедуплицировать фильмы по TMDB `movie_id`.
- Игрок не должен видеть две одинаковые кнопки для одного и того же актёра или фильма.
- Если дубликат всё же появился, игра должна выбрать одну каноническую запись и не создавать несколько переходов.

### 6.9. Игрок выбирает уже посещённого актёра

**Сценарий:** в списке кандидатов появляется актёр, который уже есть в текущей цепочке.

**Пример:**

```text
Актёр A → Фильм 1 → Актёр B → Фильм 2 → Актёр A
```

**Ожидаемое поведение:**

- Если повторы запрещены, такой актёр должен быть недоступен для выбора.
- Если повторы разрешены, игра должна явно предупреждать: «Этот актёр уже есть в цепочке».
- В базовой версии рекомендуется запрещать повторное использование актёра.
- Это уменьшает риск бесконечного цикла и делает цепочку более читаемой.

### 6.10. Игрок выбирает уже использованный фильм

**Сценарий:** игрок возвращается к фильму, который уже был использован ранее в цепочке.

**Ожидаемое поведение:**

- Если повторы фильмов запрещены, фильм должен быть недоступен.
- Если повторы разрешены, игра должна предупреждать игрока.
- В базовой версии рекомендуется запрещать повторное использование фильма.
- Это делает путь более разнообразным и снижает вероятность зацикливания.

### 6.11. Ошибка при загрузке актёров фильма

**Сценарий:** игрок выбрал фильм, но список актёров не загрузился.

**Ожидаемое поведение:**

- Игра показывает состояние загрузки.
- При ошибке показывает сообщение: «Не удалось загрузить актёров фильма».
- Игра предлагает повторить запрос.
- Игрок может вернуться к выбору фильма.
- Игра не должна фиксировать переход, пока список актёров не получен.

### 6.12. Ошибка при загрузке фильмов актёра

**Сценарий:** игрок нажал «Выбрать фильм», но список фильмов не загрузился.

**Ожидаемое поведение:**

- Игра показывает состояние загрузки.
- При ошибке показывает сообщение: «Не удалось загрузить фильмы актёра».
- Игра предлагает повторить запрос.
- Игрок может вернуться назад или завершить партию.
- Игра не должна показывать пустой список как «фильмов нет», если на самом деле произошла сетевая ошибка.

### 6.13. Целевой актёр совпадает со стартовым

**Сценарий:** генератор по ошибке выбрал одного и того же актёра в качестве старта и цели.

**Ожидаемое поведение:**

- Такая пара должна быть отклонена до начала партии.
- Генератор должен выбрать другого целевого актёра.
- Игрок не должен видеть задачу вида «дойдите от актёра A до актёра A».

### 6.14. Целевой актёр уже связан со стартовым

**Сценарий:** стартовый и целевой актёры снимались вместе в одном известном фильме.

**Ожидаемое поведение:**

- Пара допустима, но она может быть слишком простой.
- Генератор может:
  - Отклонить такую пару.
  - Использовать её только для очень простого режима.
  - Требовать минимальную длину пути больше одного шага.
- Игра не должна скрывать от игрока очевидный путь, если он существует и разрешён правилами.

### 6.15. Неполные данные о фильме или актёре

**Сценарий:** у фильма нет названия, даты, постера или корректного ID; у актёра нет имени, фото или корректного ID.

**Ожидаемое поведение:**

- Игра должна использовать безопасные заглушки: «Название недоступно», «Год неизвестен», «Фото недоступно».
- Игра не должна падать из-за отсутствия изображения или некритичного поля.
- Если у фильма нет валидного TMDB `movie_id`, его нельзя использовать для перехода.
- Если у актёра нет валидного TMDB `person_id`, его нельзя использовать в цепочке.

### 6.16. Игрок нажимает «Назад» после перехода

**Сценарий:** игрок уже подтвердил переход и хочет отменить его.

**Ожидаемое поведение:**

- Если отмена разрешена, игра должна удалить последний переход и вернуть предыдущего текущего актёра.
- Если отмена запрещена, игрок должен иметь возможность начать партию заново или сдаться.
- В базовой версии желательно разрешить отмену последнего перехода, чтобы случайный выбор не делал партию безнадёжной.
- Отмена не должна создавать дубликаты в истории цепочки.

### 6.17. Игрок закрывает приложение во время партии

**Сценарий:** игрок сворачивает или закрывает приложение в середине партии.

**Ожидаемое поведение:**

- Игра не должна считать партию автоматически выигранной или проигранной.
- При возврате игрок должен увидеть актуальное состояние партии, если её состояние было сохранено.
- Если сохранение не предусмотрено, игра должна честно сообщить, что партия не может быть восстановлена.
- В базовой версии достаточно корректно обработать возврат без потери управления и без некорректного состояния интерфейса.

### 6.18. Очень длинная цепочка

**Сценарий:** игрок строит цепочку из десятков шагов.

**Почему это проблема:**

- Интерфейс становится перегруженным.
- Растёт число запросов.
- Игрок может потерять контекст.
- Возможны ошибки и дубликаты.

**Ожидаемое поведение:**

- Игра должна показывать цепочку компактно, например в свёрнутом виде.
- Последние несколько шагов должны быть видны сразу.
- Полная цепочка должна открываться по требованию.
- Игра может предупреждать о чрезмерной длине, но не обязана принудительно завершать партию.
- Генератор должен ограничивать длину целевого пути, но игрок не должен быть ограничен искусственно без ясной причины.

### 6.19. Пустой или некорректный ответ TMDB

**Сценарий:** API вернул успешный HTTP-ответ, но тело ответа пустое, неполное или имеет неожиданную структуру.

**Ожидаемое поведение:**

- Игра не должна считать такой ответ валидными данными.
- Игра должна показать ошибку загрузки или безопасную заглушку.
- Игра не должна создавать переход на основе отсутствующих данных.
- Игра должна предложить повторить запрос.

## 7. Проверочные сценарии

### 7.1. Успешная короткая партия

```text
Старт: Актёр A
Цель: Актёр B

Актёр A → Фильм 1 → Актёр B
```

Ожидаемый результат:

- Один шаг.
- Победа сразу после выбора Актёра B.
- Цепочка отображается полностью.

### 7.2. Успешная средняя партия

```text
Старт: Актёр A
Цель: Актёр D

Актёр A → Фильм 1 → Актёр B
Актёр B → Фильм 2 → Актёр C
Актёр C → Фильм 3 → Актёр D
```

Ожидаемый результат:

- Три шага.
- Победа после третьего перехода.
- В цепочке четыре актёра и три фильма.

### 7.3. Попытка выбрать неподходящий фильм или актёра

```text
Текущий актёр: Актёр B
Выбранный фильм: Фильм X, где Актёра B нет

Выбранный фильм: Фильм 1
Выбранный актёр: Актёр Z, которого нет в Фильме 1
```

Ожидаемый результат:

- Фильм или актёр не должны быть доступны для выбора.
- Если они всё же попали в список из-за ошибки данных, переход должен быть отклонён.
- Игра должна объяснить, почему выбор невозможен.

### 7.4. Тупик после выбора актёра

```text
Актёр A → Фильм 1 → Актёр B
У Актёра B нет доступных фильмов
```

Ожидаемый результат:

- Игра сообщает о тупике.
- Игрок может отменить последний переход, если это предусмотрено.
- Игрок может сдаться или начать новую партию.

### 7.5. Потеря сети при выборе фильма или актёра

```text
Игрок нажал «Выбрать фильм»
Интернет недоступен

Игрок выбрал фильм
Интернет недоступен
Список актёров не загружается
```

Ожидаемый результат:

- Игра показывает ошибку сети.
- Игрок может повторить запрос.
- Игрок может вернуться к предыдущему экрану.
- Партия не считается завершённой автоматически.
- Переход не фиксируется, если список актёров не получен.

### 7.6. Генерация нерешаемой пары

```text
Старт: Актёр A
Цель: Актёр Z
Путь не найден
```

Ожидаемый результат:

- Игра не начинает партию.
- Игра пробует другую пару.
- После нескольких неудач показывает сообщение о невозможности подобрать пару.

### 7.7. Повторное использование актёра или фильма

```text
Актёр A → Фильм 1 → Актёр B → Фильм 2 → Актёр A
Актёр A → Фильм 1 → Актёр B → Фильм 1 → Актёр C
```

Ожидаемый результат:

- Если повторы запрещены, уже использованный актёр или фильм недоступен для выбора.
- Если повторы разрешены, игра показывает предупреждение.
- Базовая рекомендация — запретить повторы актёров и фильмов.

## 8. Принципы интерфейса

### 8.1. Понятность

Игрок всегда должен понимать:

- Кто является текущим актёром.
- Кого нужно достичь.
- Какой шаг он сейчас делает.
- Почему предложенные варианты доступны.
- Что произойдёт после подтверждения выбора.

### 8.2. Читаемость цепочки

Цепочка должна читаться сверху вниз или слева направо в едином формате:

```text
Актёр A
  → Фильм 1
  → Актёр B
  → Фильм 2
  → Актёр C
  → Фильм 3
  → Актёр D
```

Не следует смешивать актёров и фильмы в один неструктурированный список.

### 8.3. Предотвращение ошибок

Интерфейс должен:

- Не позволять выбрать фильм, в котором нет текущего актёра.
- Не позволять выбрать актёра, которого нет в выбранном фильме.
- Подтверждать переход перед его фиксацией.
- Показывать уже использованных актёров и фильмы.
- Чётко отделять ошибку загрузки от отсутствия данных.

### 8.4. Обратная связь

Каждое действие должно иметь отклик:

- Загрузка списка фильмов.
- Загрузка списка актёров.
- Успешное добавление перехода.
- Ошибка сети.
- Ошибка генерации.
- Достижение цели.
- Тупиковая ситуация.

Игрок не должен видеть бесконечную загрузку без объяснения.
