# Цикл отладки: реальный телефон + реальный TMDB

MVP проверен на JVM (Robolectric/MockWebServer). Первый запуск релизного APK
на реальном телефоне с реальным TMDB выявил проблему: игра не стартует.
Этот файл — цикл отладки: данные → гипотеза → промты **по одному за раз**.

## Файлы в `debugging/`

| Файл | Что это |
|---|---|
| `start_screen.PNG` / `start_screen.txt` | экран Home + logcat на старте приложения |
| `limit.PNG` / `limit.txt` | экран ошибки + logcat до ошибки |
| `json1.txt` | запрос+ответ TMDB `configuration` (200) |
| `json2.txt` | запрос+ответ TMDB `movie/116796/credits` (200) |
| `start_pool_130.txt` / `.csv` | результат `tools/generate_start_pool.py`: **107** актёров |

Папка зашита в `.gitignore` (в логах TMDB-ключ входит в URL) — **не коммитить**.

## Факты, уже читаемые из данных

1. **TMDB с телефона достижим**: все ответы в логах `200` (VPN сейчас работает).
   Блокировка — не причина.
2. **Экран ошибки — «Исчерпан бюджет вычислений. Попробуйте ещё раз.」**
   (`error_budget_exceeded`) — это `PairGenerationError.BudgetExceeded`:
   пара не сгенерирована, потому что исчерпан бюджет генерации.
3. **Гипотеза (высокая вероятность): wall-clock бюджет слишком мал.**
   `Budget.DEFAULT_MAX_WALL_CLOCK_MS = 6_000` (6 секунд), а сеть телефона
   гоняет TMDB ~0.6–1.1 с на запрос (первый `configuration` — 3.9 с).
   BFS успевает ~6–7 запросов — этого не хватает даже на первую пару.
4. `start_pool_130`: реально **107** актёров (130 — потолок, не цель;
   собрано 97 фильмов). ID целы; в двух строках-комментариях encoding-бит
   от переноса скрипта на твою машину («—генерировано», «попул¤рных») —
   на данные не влияет, парсим по числам.
5. **Рассогласование ID у RDJ**: в старом пуле `2871 (Robert Downey Jr.)`,
   в новом `3223 (Robert Downey Jr.)`. Имена в новом пуле пришли из TMDB
   (credits API), значит 3223 — надёжнее; 2871 проверить по `person/2871`.
   Возможно, один из старых 13 ID — «не тот человек».
6. Часы телефона стоят на 2026-11-25 (по логам). Сейчас не причина
   (TLS с TMDB прошёл), но риск для других сервисов — проверить.

## Промты (отправлять по одному, в порядке D1 → D2 → D3)

### D1. Добиться старта: почему «Исчерпан бюджет вычислений» — диагноз + фикс

**Задача.** На основе логов в `debugging/` подтвердить (или опровергнуть)
корневую причину не-старта игры и исправить: на реальной (медленной)
сети игра должна стартовать.

**Контекст.** `debugging/start_screen.txt`, `debugging/limit.txt`
(+скриншоты `start_screen.PNG`, `limit.PNG`), `debugging/json1.txt`,
`debugging/json2.txt`, `domain/util/Budget.kt`
(`DEFAULT_MAX_WALL_CLOCK_MS = 6_000`), `data/repository/GamePairRepositoryImpl.kt`
(`generatePair`), `domain/util/Bfs.kt`, `core/ui/ErrorMapper.kt`,
`docs/04_algorithms.md` §3.6 (бюджеты).

**Требования (критерии приёмки).**

- Подтвердить по логам гипотезу: wall-clock 6 с против ~1 запроса/сек →
  `BudgetExceeded` уже на первой паре.
- Минимальный фикс (варианты — решение в диалоге):
  - поднять `maxWallClockMs` под реальную сеть (60–120 с), или
  - адаптивный бюджет: после первых 2–3 запросов замерить среднюю
    задержку и выставить wall-clock из неё;
  - `maxRequests`/`maxNodesVisited` остаются жёсткими лимитами.
- `BudgetExceeded` остаётся реальным исходом, но текст ошибки ведёт
  («Проверьте соединение и попробуйте ещё раз»), а не выглядит как баг.
- UX: спиннер на время генерации до ~60 с допустим (`LoadingState` уже
  есть); ANR исключён (генерация — background-корутина).
- Алгоритмы BFS/`PairGenerator` **не** менять (минимальное вмешательство).
- Тесты: `Budget` (новые лимиты/адаптация), существующие 177+ зелёные,
  `detekt`/`lint` зелёные.

**Результат.** На телефоне: «Начать игру» → пара показана (загрузка до
~60 с допустима), игровая сессия работает. Если ошибка повторится —
новый лог `debugging/step2_start.txt` и следующая итерация D1.

### D2. Пул: 107 актёров из `start_pool_130` в `PAIR_ACTORS`

> Примечание: это обновление планировалось ещё в MVP-цикле (под него
> написан `tools/generate_start_pool.py`), но в `docs/post_mvp_prompts.md`
> не попало — это разовое обновление данных, а не пост-MVP фича, поэтому
> оно здесь. **Отправлять после D1** (иначе проверка на телефоне
> невозможна: без фикса бюджета генерация не завершится).

**Задача.** Заменить зашитые 13 звёзд на 107 актёров из
`debugging/start_pool_130.txt`.

**Контекст.** `debugging/start_pool_130.txt` (107 ID),
`data/repository/GamePairRepositoryImpl.kt` (`PAIR_ACTORS`, 13 звёзд,
пары 13×12=156), `app/src/test/.../GamePairRepositoryImplTest.kt`,
`tools/generate_start_pool.py`.

**Требования.**

- 107 ID взять из txt (комментарии в нём могут быть биты — парсим
  по числам).
- Старые 13 звёзд — **объединение**: не входящие в новый список —
  оставить; каждый из 13 проверить по `person/{id}` (VPN): имя
  соответствует. Обязательный кейс RDJ: `2871` (старый) vs `3223`
  (новый) — оставить канонический ID, дубликат убрать.
- Спотовая проверка ~10 случайных ID из нового пуля по `person/{id}`.
- Пары — автоматически N×(N−1) (11k+); `generatePair` и целевой BFS
  не меняются.
- Тесты: размер пула, число пар, нет дублей/само-пар; 6 тестов
  `GamePairRepositoryImplTest` зелёные; 177+ тестов, `detekt`/`lint`.
- README: примечание про пул (107 актёров, data-driven, как
  регенерировать скриптом).

**Результат.** `PAIR_ACTORS` — 107+ проверенных TMDB актёров; пул можно
регенерировать запуском скрипта, без изменения кода.

### D3. Закрыть MVP: полный смоук на телефоне (после D1+D2)

**Задача.** Прогнать на реальном телефоне с реальным TMDB сценарии
B1–B11 и таблицу бюджетов C из `docs/QA_CHECKLIST.md`; при полном
зелёном — тег `v0.1.0-mvp`.

**Контекст.** `docs/QA_CHECKLIST.md`, фиксы D1/D2, APK из
`assembleRelease`.

**Требования.**

- B1–B11: старт → пара → переход → результат → сессия (Room);
  офлайн (VPN выключен) — баннер + экраны ошибок.
- Таблица C (бюджеты): число запросов за игру — в пределах лимитов.
- Найденные дефекты — отдельные `[fix]` коммиты, затем повтор смоука.
- Всё зелёное: тег `v0.1.0-mvp`, commit + push (после твоего одобрения).

## Правила цикла

- Логи/скриншоты — в `debugging/` (папка в `.gitignore`; TMDB-ключ
  в логах входит в URL).
- Commit/push — только после твоего явного одобрения.
